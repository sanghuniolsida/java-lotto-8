## 📋기능 요구 사항 체크리스트

### 입력
- [ ] 로또 구입 금액을 입력받는다.
- [ ] 당첨 번호 6개를 쉼표(,)로 구분해 입력받는다.
- [ ] 보너스 번호 1개를 입력받는다.

### 로또 발행
- [x] 구입 금액에 해당하는 로또 장수를 계산한다 (장당 1,000원).
- [ ] 각 로또는 1~45 범위의 **중복되지 않는** 숫자 6개로 구성한다.
- [ ] 발행된 각 로또 번호를 **오름차순**으로 **정렬**한다.
- [ ] 랜덤 번호 생성은 `camp.nextstep.edu.missionutils.Randoms.pickUniqueNumbersInRange()`를 활용한다.

### 당첨 번호/보너스 번호 검증
- [ ] 당첨 번호 6개의 범위를 검증한다 (1~45).
- [ ] 당첨 번호 6개 간 **중복이 없는지** 검증한다.
- [ ] 보너스 번호의 범위를 검증한다 (1~45).
- [ ] 보너스 번호가 당첨 번호 6개와 **중복되지 않는지** 검증한다.

### 결과 계산
- [ ] 사용자 보유 로또와 당첨 번호를 비교해 일치 개수를 계산한다.
- [ ] 1등(6개) / 2등(5개+보너스) / 3등(5개) / 4등(4개) / 5등(3개) 판정을 수행한다.
- [ ] 각 등수별 당첨 개수를 집계한다.
- [ ] 총 상금과 수익률을 계산한다 (수익률 = 총 상금 / 총 구매 금액 × 100).
- [ ] 수익률을 **소수점 둘째 자리에서 반올림**해 출력 형식에 맞춘다 (예: `62.5%`).

### 출력
- [ ] 구매한 로또 수량을 출력한다 (예: `8개를 구매했습니다.`).
- [ ] 각 로또의 번호를 오름차순으로 출력한다 (한 줄에 한 장).
- [ ] “당첨 통계” 섹션을 출력한다 (구분선 포함).
- [ ] 등수별 결과를 출력한다.
- [ ] 최종 수익률 문구를 출력한다 (예: `총 수익률은 62.5%입니다.`).

### 예외 처리 (재입력 플로우)
- [ ] 잘못된 입력이 들어오면 `IllegalArgumentException`을 발생시킨다.
- [ ] 예외 메시지는 **`[ERROR]`로 시작**한다.
- [ ] 예외 발생 시 해당 단계부터 **입력을 다시 받는다**.
- [ ] 다음 상황을 모두 예외로 처리한다:
    - [ ] 구입 금액이 1,000원 단위가 아님 / 0 이하.
    - [ ] 당첨 번호 개수가 6개가 아님.
    - [ ] 번호가 1~45 범위를 벗어남.
    - [ ] 당첨 번호 간 중복 존재.
    - [ ] 보너스 번호가 범위를 벗어나거나 당첨 번호와 중복.

### 도메인/설계 제약(기능 관점)
- [x] 제공된 `Lotto` 클래스를 사용하며, 생성 시 번호 개수(6개)를 검증한다.
- [ ] 등수/상금 정보를 **Enum**으로 관리한다 (일치 개수, 보너스 포함 여부, 상금).

## ⚙️프로그래밍 요구 사항 체크리스트

### 요구 사항 1
- [x] JDK 21에서 빌드 및 실행된다 (`java -version`으로 확인).
- [x] `build.gradle`은 수정하지 않는다(제공 라이브러리 이외 외부 라이브러리 추가 금지).
- [ ] 프로그램 종료 시 `System.exit()`를 호출하지 않는다.
- [x] 프로젝트의 시작점은 `Application.main()`이다.

### 요구 사항 2,3
- [ ] indent(들여쓰기) depth가 2 이내이다(3 초과 금지).
- [ ] 삼항 연산자(`?:`)를 사용하지 않는다.
- [ ] `else`를 사용하지 않는다.
- [ ] `switch/case`를 사용하지 않는다.
- [ ] 메서드는 한 가지 일만 하며, 길이가 15라인을 넘지 않는다.
- [ ] 상수(매직 넘버/문구)는 의미 있는 이름의 상수로 분리한다.
- [ ] `Enum`을 사용해 등수/상금 등 도메인 상수를 표현한다.
- [ ] 유효하지 않은 입력에 대해 `IllegalArgumentException` 또는 `IllegalStateException` 등 **명확한 유형**의 예외를 사용한다.
- [ ] 모든 에러 메시지는 `"[ERROR]"`로 시작한다.
- [ ] 예외 발생 시 해당 단계부터 입력을 다시 받도록 흐름을 설계한다.
- [ ] JUnit 5를 사용해 도메인/서비스 로직의 단위 테스트를 작성한다(UI 입출력 로직 제외).
- [ ] 모든 테스트가 성공 시 `BUILD SUCCESSFUL`이 출력됨을 확인한다.
